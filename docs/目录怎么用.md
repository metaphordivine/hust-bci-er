# 目录怎么用

目标：这个仓库只保留重要模型、统一评估口径、深度验证方法。  
原则：**组件复用 + 路线配置 + 统一评估 + 可追溯审计**。

## 顶层目录

目录名用英文，中文解释写在文档里，方便脚本、CI、import 和多人协作。

```text
hust-bci-er/
  configs/        # 配置：路线、数据集、评估协议
  src/            # 源码：可复用组件
  scripts/        # 稳定命令入口
  reports/        # 简短路线总结
  docs/           # 项目文档
  tests/          # 自动测试
  agent_protocols/ # 平台无关协作/审计流程
  .github/        # GitHub Actions 云端检查
  outputs/        # 本地训练/评估输出，不提交
  scratch/        # 临时探索脚本，默认不进主线
```

## src 目录

```text
src/hust_bci_er/
  config/          # route schema、组件注册表、配置校验
  contracts/       # 数据对象契约：sample、batch、prediction、manifest
  data/            # 数据读取、manifest、subject split
  preprocessing/   # EA、whitening、滤波、zscore
  features/        # 微分熵、bandpower、Hjorth、连接特征
  models/          # 模型实现
  adaptation/      # AdaBN、DANN、domain loss
  training/        # trainer、loss、sampler、callback
  inference/       # Top-4、score fusion
  evaluation/      # 指标、P1/P2/P3、crop policy、worst crop stress test
  audit/           # no-leakage、artifact manifest、报告生成
```

## models 目录

模型不要堆成 `model_v2_final.py`。按层拆：

```text
models/
  backbones/       # EEGNet、Conformer、Deformer、SRFNet
  graph/           # LGGNet、adjacency、图输入
  heads/           # linear、MLP 等输出头
  factory.py       # 按 config 创建模型
```

## evaluation 目录

评估最容易乱，要拆开：

```text
evaluation/
  metrics.py       # BA、AUC、all-correct
  protocols/       # P1/P2/P3
  crop_policy.py   # crop1-5、random、worst 的评估调用
  topk_policy.py   # Top-4 后处理
  stress_tests.py  # worst crop 等压力测试
  report.py        # 生成 summary
```

注意：

```text
Top-4 分组规则       -> inference/
crop1-5/random/worst -> evaluation/
```

## 配置必须可校验

每条路线只写 config，不复制大脚本。

```text
configs/
  routes/
    models/
  datasets/
  protocols/
  splits/
  statuses.yaml
  audit_decisions.yaml
```

所有模型路线先放 `configs/routes/models/`，默认平等。状态只写在 route config 里。

route config 必须包含：

```yaml
route_id: ea_deformer
status: IDEA
dataset_version: train_v1
split_id: p1_seed42_fold0
seed: 42
input_window_sec: 10
preprocessing: [euclidean_alignment, zscore]
features: []
model:
  name: deformer_lite
adaptation: none
inference:
  top4: true
  crop_policy: single
evaluation:
  protocol: p1_repeated_group_kfold
  primary_metric: exact_single_crop_expected_BA
```

校验入口：

```bash
python scripts/validate_route.py configs/routes/models/ea_deformer.yaml
```

校验内容：

| 检查 | 目的 |
|---|---|
| `route_id` 唯一 | 防止覆盖实验 |
| 组件名必须在 registry | 防止拼写漂移 |
| `seed` / `split_id` 必填 | 保证可复现 |
| evaluation 协议合法 | 防止 P1/P2/P3 混用 |
| output_dir 自动派生 | 防止覆盖旧输出 |

`model.name` 目前分层管理：

```text
TORCH_BACKBONES   # 可训练神经网络 backbone
SKLEARN_MODELS    # 表格/手工特征模型
GRAPH_MODELS      # 图模型
SCORE_ROUTE_MODELS # 分数组装路线，不调用 torch model factory
```

## 路线生命周期

每条路线必须有状态：

```text
IDEA
SMOKE_ONLY
DIAGNOSTIC_ONLY
CANDIDATE
PROMOTED
REJECTED
ARCHIVED
```

标准状态声明放在：

```text
configs/statuses.yaml
```

状态表示路线生命周期，不表示模型天生优劣。新路线默认从 `IDEA` 开始。

一次审查的结论单独放在：

```text
configs/audit_decisions.yaml
```

`BLOCKED` 是审查结论，不是 route status；被 `BLOCKED` 的路线保持原状态，直到缺失项补完。

总表放：

```text
reports/route_board.md
```

用于回答：

```text
这条路线还能不能信？
是候选、诊断、废案，还是历史保留？
最后一次可信结果在哪里？
```

这个总表由脚本生成，不手写维护：

```bash
python scripts/update_route_board.py
python scripts/update_route_board.py --check
```

## Artifact Manifest

每次运行都生成：

```text
outputs/<route_id>/<run_id>/manifest.json
```

至少记录：

```json
{
  "audit_schema_version": 1,
  "route_id": "whitening_srfnet_eps1e3",
  "git_commit": "...",
  "config_path": "...",
  "config_snapshot_path": "config_snapshot.yaml",
  "config_sha256": "...",
  "dataset_manifest_sha256": "...",
  "split_id": "...",
  "split_sha256": "...",
  "seed": 42,
  "command": "...",
  "primary_metric": "exact_single_crop_expected_BA",
  "prediction_csv": "predictions.csv",
  "prediction_sha256": "..."
}
```

`config_sha256` 指向 run 目录内的 config snapshot。当前 route config 后续演化时，旧 run 仍以 snapshot 为准。

## scripts 只放稳定入口

```text
scripts/
  validate_route.py
  audit_experiment.py
  update_route_board.py
  repo_doctor.py
```

临时脚本放 `scratch/`，不要污染主线。

当前统一命令：

```bash
python scripts/repo_doctor.py fast
python scripts/repo_doctor.py experiment --route configs/routes/models/ea_deformer.yaml --run outputs/ea_deformer/20260514_120000 --gate candidate
```

## Agent Protocol

Agent 流程不写成 Codex 专用 Skill，而是平台无关协议：

```text
AGENTS.md
agent_protocols/experiment_audit.md
```

任何协作者、AI assistant、本地脚本、GitHub Actions 都按同一套命令判断：

```bash
python scripts/repo_doctor.py fast
```

有实验输出时再跑：

```bash
python scripts/repo_doctor.py experiment --route <route_config> --run <run_dir>
```

核心原则：

```text
协议负责说明流程；
scripts 负责返回 pass/fail；
tests 负责固化红线；
CI 负责云端复查。
```

## reports 只放简短总结

每条重要路线只提交一个：

```text
reports/route_summaries/<route_id>_summary.md
```

summary 固定包含：

```text
status
config path / hash
dataset / split / seed
protocol
Top-4 / no-Top4 / all-correct
decision
risk notes
reproduce command
```

详细 CSV、checkpoint、trial 级预测留在 `outputs/`，不提交。

## tests 必须覆盖红线

```text
tests/
  test_route_schema.py
  test_no_public_private_label_usage.py
  test_no_id_shortcut.py
  test_subject_split_integrity.py
  test_top4_group_size.py
  test_metrics.py
  test_public_inference_no_label.py
```

重点检查：

| 测试 | 目的 |
|---|---|
| public/private label 不被训练读取 | 防泄露 |
| subject_id / trial_id 不作为特征 | 防 ID shortcut |
| train/val/test subject 不交叉 | 防 subject leakage |
| 每个 subject 恰好 8 trials | 防 Top-4 错位 |
| public inference 不读取 `y_true` | 防伪装无监督 |

prediction CSV 允许 `subject_id` 或 `user_id` 作为分组 metadata；这些字段只能用于分组、Top-4 和审计，不能作为模型特征。

## 协作规则

1. 新方法先放组件目录。
2. 新实验只新增 route config。
3. 所有 route config 必须先 validate。
4. 每次运行必须生成 manifest。
5. 重要结果只提交一个 summary。
6. 不提交 checkpoint、raw outputs、trial 级预测。
7. 不使用 public/private labels、leaderboard feedback、ID shortcut。

# 目录怎么用

目标：这个仓库只保留重要模型、统一评估口径、深度验证方法。  
原则：**组件复用 + 路线配置 + 统一评估 + 可追溯审计**。

## 顶层目录

目录名用英文，中文解释写在文档里，方便脚本、CI、import 和多人协作。

当前仓库分成三种成熟度：

```text
已实现：schema、registry、审计、基础组件、Top-4、score route 最小组装、P1/P2/P3 dry-run plan 和 runner manifest。
预留边界：真实 HUST EEG dataset loader、真实训练 job adapter、graph、heads、callback。
实验空缺：当前没有 candidate 级真实结果，dataset/split manifest 仍需正式证据。
```

文档里的目录边界表示协作约定；如果目录只有 `__init__.py`，它就是预留位置，不代表完整能力已经实现。

```text
hust-bci-er/
  configs/        # 配置：路线、数据集、评估协议
  src/            # 源码：可复用组件
  scripts/        # 稳定命令入口
  reports/        # 简短路线总结
  docs/           # 项目文档
  tests/          # 自动测试
  agent_protocols/ # 平台无关协作/审计流程
  .github/        # GitHub Actions 云端检查
  outputs/        # 本地训练/评估输出，不提交
  scratch/        # 临时探索脚本，默认不进主线
```

## src 目录

```text
src/hust_bci_er/
  config/          # route schema、组件注册表、配置校验
  contracts/       # 数据对象契约：sample、batch、prediction、manifest
  data/            # 数据读取、manifest、subject split
  preprocessing/   # EA、whitening、滤波、zscore
  features/        # 微分熵、bandpower、Hjorth、连接特征
  models/          # 模型实现
  adaptation/      # AdaBN、DANN、domain loss
  training/        # trainer、loss、sampler、callback
  inference/       # Top-4、score fusion
  evaluation/      # 指标、P1/P2/P3、crop policy、worst crop stress test
  audit/           # no-leakage、artifact manifest、报告生成
```

## models 目录

模型不要堆成 `model_v2_final.py`。按层拆：

```text
models/
  backbones/       # EEGNet、Conformer、Deformer、SRFNet
  graph/           # LGGNet、adjacency、图输入
  heads/           # linear、MLP 等输出头
  factory.py       # 按 config 创建模型
```

## evaluation 目录

评估最容易乱，要拆开：

```text
evaluation/
  metrics.py       # BA、AUC、all-correct
  protocols/       # P1/P2/P3
  crop_policy.py   # crop1-5、random、worst 的评估调用
  topk_policy.py   # Top-4 后处理
  stress_tests.py  # worst crop 等压力测试
  report.py        # 生成 summary
```

注意：

```text
Top-4 分组规则       -> inference/
crop1-5/random/worst -> evaluation/
```

## 配置必须可校验

每条路线只写 config，不复制大脚本。

```text
configs/
  routes/
    models/
  datasets/
  protocols/
  splits/
  statuses.yaml
  audit_decisions.yaml
```

所有模型路线先放 `configs/routes/models/`，默认平等。状态只写在 route config 里。

route config 必须包含：

```yaml
route_id: ea_deformer
status: IDEA
dataset_version: train_v1
split_id: p1_seed42_fold0
seed: 42
input_window_sec: 10
preprocessing: [euclidean_alignment, zscore]
features: []
model:
  name: deformer_lite
adaptation: none
inference:
  top4: true
  crop_policy: single
evaluation:
  protocol: p1_repeated_group_kfold
  primary_metric: exact_single_crop_expected_BA
```

校验入口：

```bash
python scripts/validate_route.py configs/routes/models/ea_deformer.yaml
```

校验内容：

| 检查 | 目的 |
|---|---|
| `route_id` 唯一 | 防止覆盖实验 |
| 组件名必须在 registry | 防止拼写漂移 |
| `seed` / `split_id` 必填 | 保证可复现 |
| evaluation 协议合法 | 防止 P1/P2/P3 混用 |
| output_dir 自动派生 | 防止覆盖旧输出 |

`model.name` 目前分层管理：

```text
TORCH_BACKBONES   # 可训练神经网络 backbone
SKLEARN_MODELS    # 表格/手工特征模型
GRAPH_MODELS      # 图模型
SCORE_ROUTE_MODELS # 分数组装路线，不调用 torch model factory
```

`model.name: score_fusion` 还必须声明并匹配注册表：

```yaml
model:
  name: score_fusion
  score_node: conformer_srfnet_score_average
  components: [conformer_component, srfnet_long_component]
```

`score_node/components` 必须和 `src/hust_bci_er/inference/clean_score_routes.py` 中的注册项一致；非 `score_fusion` 路线不能声明这两个字段。

route config 不能手写 `output_dir`，输出目录由 `route_id/run_id` 自动派生。

## 路线生命周期

每条路线必须有状态：

```text
IDEA
SMOKE_ONLY
DIAGNOSTIC_ONLY
CANDIDATE
PROMOTED
REJECTED
ARCHIVED
```

标准状态声明放在：

```text
configs/statuses.yaml
```

状态表示路线生命周期，不表示模型天生优劣。新路线默认从 `IDEA` 开始。

一次审查的结论单独放在：

```text
configs/audit_decisions.yaml
```

`BLOCKED` 是审查结论，不是 route status；被 `BLOCKED` 的路线保持原状态，直到缺失项补完。

总表放：

```text
reports/route_board.md
```

用于回答：

```text
这条路线还能不能信？
是候选、诊断、废案，还是历史保留？
最后一次可信结果在哪里？
```

这个总表由脚本生成，不手写维护：

```bash
python scripts/update_route_board.py
python scripts/update_route_board.py --check
```

## Artifact Manifest

每次运行都生成：

```text
outputs/<route_id>/<run_id>/manifest.json
```

至少记录：

```json
{
  "audit_schema_version": 2,
  "route_id": "whitening_srfnet_eps1e3",
  "git_commit": "...",
  "config_path": "...",
  "config_snapshot_path": "config_snapshot.yaml",
  "config_sha256": "...",
  "dataset_manifest_path": "configs/datasets/train_v1.yaml",
  "dataset_manifest_sha256": "...",
  "split_manifest_path": "configs/splits/p1_seed42_fold0.yaml",
  "split_id": "...",
  "split_sha256": "...",
  "seed": 42,
  "command": "...",
  "primary_metric": "exact_single_crop_expected_BA",
  "metrics": {"exact_single_crop_expected_BA": 0.0},
  "metric_inputs": {
    "score_matrix_csv": "score_matrix.csv",
    "score_matrix_sha256": "..."
  },
  "prediction_csv": "predictions.csv",
  "prediction_sha256": "...",
  "environment": {"python": {"version": "..."}, "packages": {}, "torch": {}},
  "determinism": {
    "python_seed": 42,
    "python_hash_seed": 42,
    "pythonhashseed_env": "42",
    "numpy_seed": 42,
    "torch_seed": 42,
    "deterministic_algorithms": true,
    "cudnn_deterministic": true,
    "cudnn_benchmark": false,
    "dataloader_worker_seed_base": 42,
    "batch_order": {"policy": "seeded_sampler_or_shuffle_false", "sampler_seed": 42}
  },
  "checkpoint_selection": {
    "rule": "best_monitored_epoch",
    "monitor": "val_loss",
    "mode": "min",
    "tie_break": "earliest_epoch"
  },
  "crop_policy": {"name": "single", "selection": "route_default_single_crop", "tie_break": "not_applicable"},
  "environment_lock": {"files": [{"path": "environment.lock", "sha256": "..."}, {"path": "requirements.lock", "sha256": "..."}]}
}
```

`config_sha256` 指向 run 目录内的 config snapshot。当前 route config 后续演化时，旧 run 仍以 snapshot 为准。

`prediction_record_level` 默认是 `trial`。如果一个 prediction CSV 合并了多个 fold 或 seed，在 manifest 里声明：

```json
{
  "top4_group_keys": ["seed", "fold", "subject_id"]
}
```

candidate/promoted gate 下必须能复算 route 声明的主指标：

```text
exact_single_crop_expected_BA -> 需要 metric_inputs.score_matrix_csv
top4_BA / no_top4_BA         -> 需要 y_true + y_pred
all_correct_rate             -> 需要分组后的 y_true + y_pred
```

Top-4 审查不仅检查每组 8 行、4 个 positive，还会检查：

```text
trial_id 唯一
pred_top4 只能是 0/1
y_true 在 8 trial 中为 4 个 positive
pred_top4 必须等于 score 排序得到的 Top-4
```

candidate/promoted gate 下，run-specific split/dataset 证据也必须可审计：

```text
split evidence:
  必须有正式 subject list 或 fold definitions
  必须有 trial_rows 作为 trial index
  subject list / fold definitions 必须和 trial_rows 中的 subject membership 一致
  train/val/test subject 不交叉
  original_trial 不跨 split
  trial_rows 带 fold 时，按 fold 分别检查

dataset evidence:
  data_sources 非空
  checksum_manifest 非空
  checksum path 覆盖 data_sources path
  checksum 使用 64 位小写 sha256
  多余 checksum path 会作为未解决 warning 记录
```

占位 dataset/split manifest 只适合 IDEA、smoke 或 diagnostic 阶段，不能支撑 candidate/promoted。
protocol runner 生成的 `materialized_without_subject_index` split contract 也只是 job-specific 占位锁，不能支撑 candidate/promoted。

## scripts 只放稳定入口

```text
scripts/
  validate_route.py
  audit_experiment.py
  assemble_score_route.py
  plan_evaluation_protocol.py
  update_route_board.py
  repo_doctor.py
```

临时脚本放 `scratch/`，不要污染主线。

当前统一命令：

```bash
python scripts/repo_doctor.py fast
python scripts/repo_doctor.py experiment --route configs/routes/models/ea_deformer.yaml --run outputs/ea_deformer/20260514_120000 --gate candidate
python scripts/repo_doctor.py experiment --route configs/routes/models/ea_deformer.yaml --gate smoke
```

score route 可从 component score CSV 组装成 prediction table：

```bash
python scripts/assemble_score_route.py \
  --route configs/routes/models/conformer_srfnet_score_average.yaml \
  --component-score conformer_component=<conformer_scores.csv> \
  --component-score srfnet_long_component=<srfnet_scores.csv> \
  --output outputs/<route_id>/<run_id>/predictions.csv
```

P1/P2/P3 评估协议可以先 dry-run 看工作量和用途：

```bash
python scripts/plan_evaluation_protocol.py --protocol p1 --route-config configs/routes/models/ea_deformer.yaml
python scripts/plan_evaluation_protocol.py --protocol p2 --route-config configs/routes/models/ea_deformer.yaml
python scripts/plan_evaluation_protocol.py --protocol p3 --route-config configs/routes/models/ea_deformer.yaml --grid-size ea_deformer=6
```

不同 protocol 的用途见 `docs/04_evaluation_protocols.md`。

`repo_doctor.py fast` 会运行：

```text
check_repo_conventions
check_route_registry
validate_route --all
update_route_board --check
check_summary_consistency
compileall src scripts
pytest tests
```

Torch 模型 forward smoke 是独立的可选 gate，避免默认 fast gate 下载大依赖：

```bash
pip install -e ".[dev,models]"
python scripts/model_smoke.py
```

GitHub 上 `.github/workflows/model_smoke.yml` 会在模型路径相关 PR 或手动触发时运行这条 smoke。

Toy end-to-end audit smoke 用于验证平台闭环，不代表真实 EEG 成绩：

```bash
python scripts/launch_reproducible.py --seed 42 -- python scripts/toy_experiment_audit.py --run-dir outputs/toy_eegnet/onboarding
```

## Agent Protocol

Agent 流程不写成 Codex 专用 Skill，而是平台无关协议：

```text
AGENTS.md
agent_protocols/experiment_audit.md
agent_protocols/foundation_usage.md
agent_protocols/skill_router.md
```

任何协作者、AI assistant、本地脚本、GitHub Actions 都按同一套命令判断：

```bash
python scripts/repo_doctor.py fast
```

有实验输出时再跑：

```bash
python scripts/repo_doctor.py experiment --route <route_config> --run <run_dir> --gate candidate
```

核心原则：

```text
人类描述场景；
agent 自动选择 skill；
协议负责说明流程；
scripts 负责返回 pass/fail；
tests 负责固化红线；
CI 负责云端复查。
```

如果人类说“比较 P1/P2/P3 的工作量”，agent 应该自动使用 Evaluation Protocol Planning Skill；如果人类说“这个 run 能不能进 candidate”，agent 应该自动使用 Experiment Audit Skill。具体映射见 `agent_protocols/skill_router.md`。

如果人类说“让 agent 用公共基座串起 dataset/split/run artifact”或类似需求，agent 应该自动使用 Foundation Usage Skill，先读 `agent_protocols/foundation_usage.md`，再按其中的 foundation map 选择 dataset manifest、split manifest、determinism、run manifest、prediction/report、promotion、registry/cache/monitor 等稳定入口。

多人协作是 human-led：`reports/route_registry.yaml` 只记录 route owner、当前 blocker 和共享谨慎修改路径；不做 agent team 调度。协作细节见 `docs/collaboration_workflow.md`。

## reports 只放简短总结

每条重要路线只提交一个：

```text
reports/route_summaries/<route_id>_summary.md
```

summary 固定包含：

```text
route_id
route_status
audit_decision
gate
primary_metric
decision
reproduce
dataset / split / seed
protocol
risk notes
```

高级状态路线还必须绑定可审计证据：

```text
audit_report_path
manifest_path
manifest_sha256
primary_metric_value
```

`check_summary_consistency.py` 会检查这些路径不逃逸仓库、manifest sha256 匹配、manifest JSON 合法、route_id / primary_metric 一致，并确认 `primary_metric_value` 与 manifest 的 `metrics` 字段一致。

详细 CSV、checkpoint、trial 级预测留在 `outputs/`，不提交。

promoted gate 还需要：

```text
reports/promotion_audits/<route_id>_promotion.md
```

promotion audit 必须按 `reports/promotion_audits/_template.md` 填写，并引用一个 `gate == candidate`、`overall == PASS` 且关键规则通过的 candidate audit report。

## tests 必须覆盖红线

```text
tests/
  test_route_schema.py
  test_no_public_private_label_usage.py
  test_no_id_shortcut.py
  test_subject_split_integrity.py
  test_top4_group_size.py
  test_metrics.py
  test_public_inference_no_label.py
```

重点检查：

| 测试 | 目的 |
|---|---|
| public/private label 不被训练读取 | 防泄露 |
| subject_id / trial_id 不作为特征 | 防 ID shortcut |
| train/val/test subject 不交叉 | 防 subject leakage |
| 每个 subject 恰好 8 trials | 防 Top-4 错位 |
| public inference 不读取 `y_true` | 防伪装无监督 |

prediction CSV 允许 `subject_id` 或 `user_id` 作为分组 metadata；这些字段只能用于分组、Top-4 和审计，不能作为模型特征。

## 协作规则

1. 新方法先放组件目录。
2. 新实验只新增 route config。
3. 所有 route config 必须先 validate。
4. 每次运行必须生成 manifest。
5. 重要结果只提交一个 summary。
6. 不提交 checkpoint、raw outputs、trial 级预测。
7. 不使用 public/private labels、leaderboard feedback、ID shortcut。
